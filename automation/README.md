# Automation State

`automation/state.json` stores the persistent ranked performer queue, active performer, shuffled no-repeat surah queue for that performer, completed performer/surah pairs, unavailable pairs with reasons, shuffled no-repeat background queue, cycle number, cached playlist IDs, pending post-upload checkpoint, last successful upload time, last success, and recent failures.

The order comes from `config/automation_reciters.json`; alternate recordings of one performer share completion history. A performer is retained until every available surah is completed. Queue exhaustion never restarts completed performers. Schema-v1 migration resets only the mixed-performer surah queue, retains independent background/playlist state, and imports known upload completions. The deployed migration also recovered successful uploads from Git history.

The workflow commits successful production state and durable post-upload checkpoints even after a later step fails. Manual dry runs preserve state unless `advance_state=true`. Post-upload recovery reuses the uploaded video, marks its surah complete, and leaves the next render for the next interval. Scheduling uses `last_success_at`, with a legacy Git timestamp fallback, and retries pending checkpoints at the next scheduled check.

Do not edit this file while a workflow is running. Rendered videos, thumbnails, audio downloads, logs, and credentials are never stored here.
